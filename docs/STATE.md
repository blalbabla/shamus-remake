# Shamus 3D: состояние разработки (handoff)

Документ для продолжения работы на другой машине. Дата: 2026-11-16.
Репозиторий: <https://github.com/blalbabla/shamus-remake>, ветка `main`.

Это снимок текущего состояния, а не замена [DESIGN.md](DESIGN.md), [TECHNICAL.md](TECHNICAL.md) и
[MAZE_FORMAT.md](MAZE_FORMAT.md). Если меняешь механику или архитектуру, обновляй и их.

## 1. Что это

Бесплатный ремейк Shamus (Synapse, 1982): 128 комнат, 4 уровня, враги, ключи и замки, pod-комнаты,
Shadow, процедурные лабиринты. Вид сверху или изометрия, всё из 3D-примитивов, звук синтезируется кодом.
Стек: .NET 10, C#, Raylib-cs 8.1.0, xUnit.

Статус: играбельный MVP. Все базовые механики оригинала на месте, плюс процедурные лабиринты,
карта, рекорды, настройки, освещение с тенями. Визуально «одеты» игрок и все три врага, есть снаряды
с эффектами (вспышка, шлейф, взрыв). Звук пока не перерабатывался в этой итерации.

## 2. Быстрый старт на новой машине

Нужны:

- Windows 10/11 (проект проверялся на Windows; Raylib-пакет тянет нативные библиотеки сам).
- .NET SDK 10.0.x (проверено на 10.0.301/10.0.302). Проверка: `dotnet --version`.
- GPU/драйвер с OpenGL 3.3 (шейдер освещения). Без него игра запустится без света (fallback).
- Интернет для `dotnet restore` (NuGet: Raylib-cs, xUnit).

```bash
git clone https://github.com/blalbabla/shamus-remake.git
cd shamus-remake
dotnet build          # решение Shamus.sln
dotnet test           # 83 теста ядра
dotnet run --project src/Shamus.Game
```

> Каталог называется `shamus-remake` после клонирования; в этом документе пути указаны от корня репозитория.

Полезные флаги:

| Флаг | Назначение |
|---|---|
| `--maze c64\|atari\|holmes\|cluseau\|marlowe\|bond\|random` | лабиринт |
| `--seed N` | зерно для `random` |
| `--room N` | сразу в комнату N, без титульного экрана |
| `--view top\|iso` | вид камеры |
| `--settings` | открыть экран настроек (для отладки/скриншотов) |
| `--winsize WxH` | стартовый размер окна (проверка полей 16:9) |
| `--shot файл.png` | сохранить кадр (по умолчанию 8-й) и выйти |
| `--shotframe N` | какой кадр снимать `--shot` (ловля эффектов: выстрела, попадания) |
| `--fire` | отладка: постоянно держать огонь, чтобы на скриншот попали снаряды и эффекты |
| `--zoom F`, `--look X,Y` | отладочный зум и точка обзора |
| `--mute` | без звука |
| `--debug` | `[` / `]` переключают комнаты |

Настройки пользователя и рекорды: `%APPDATA%\Shamus3D\settings.json` (на новой машине создаются заново).
Там же хранятся `Fullscreen`, громкость, выбранный лабиринт, сложность, God mode, вид камеры.

`assets/config.json` читается из исходного дерева (игра ищет каталог, где есть `assets` и `src`), поэтому
в dev-запуске правки конфига подхватываются без пересборки (F5 в игре перезапускает комнату с новым
конфигом). Для publish копия тоже кладётся рядом с exe — см. §7.

## 4. Что реализовано

- **Мир:** 128 комнат, 4 уровня; chamber/corridor/pod; двери с ключами; границы комнат 0 и 127 запечатаны.
- **Симуляция:** детерминированный `GameWorld.Tick` (60 Hz), 3 типа врагов, пули, объекты, Shadow,
  pod-барьеры, новые круги; сложность и God mode через `GameConfig`. Правило «сначала разворот,
  потом движение» для танка — часть симуляции, а не вида.
- **Лабиринты:** 6 оригинальных `.maze` + процедурный генератор с валидатором; `.map`-раскладка карты.
- **Игрок:** танк (гусеницы, корпус, башня-полусфера, ствол), плавный доворот, снаряд из дула.
- **Враги:** Robo-Droid (гусеницы + барабан с пазом и бегущим маяком), Spiral Drone («тарелка» со
  шпильками и башней с тремя щелями-портами), Snap Jumper (гранёный кристалл: телепорт + мерцание).
  Окрас случайный из четырёх цветов без зелёного, детерминированно.
- **Снаряды и эффекты:** пуля игрока — маленький цилиндр с конусом, стартует из дула; болты врагов —
  плазменные шарики из своих портов; вспышка у дула, дымный шлейф с огнём, взрыв со искрами и дымом.
- **Предметы:** ключ (кольцо, стержень, бородка) и скважина (диск с чёрной скважиной) лежат плашмя в обеих
  проекциях; зелье — большой плюс, «?» — знак вопроса. Все левитируют; ключ вращается, плюс и «?» в
  изометрии стоят вертикально и вращаются, сверху лежат и не вращаются.
- **Рендер:** ортокамера сверху/изометрия; letterbox 16:9 в окне любого размера и в fullscreen
  (рендер в родном разрешении окна/дисплея, MSAA 4x); стены — вертикальные полупрозрачные розовые
  силовые поля; столбики-генераторы; направленный свет с тенями (2048, PCF 5x5); свечение (glow)
  силовых полей, «шапок» генераторов, барьеров pod-комнат, снарядов и эффектов. Высоты всего, что
  стоит в комнате, согласованы через `RoomMetrics`. В изометрии комната — плита-плато по доступной зоне
  (chamber — толстый «+», коридор — проход), стены по контуру, снаружи обрыв.
- **UI:** титульный экран (только меню), SETTINGS (Gameplay/Video/Audio), пауза, Game Over, карта,
  HUD, тосты, рекорды по лабиринтам.
- **Ввод:** клавиатура и геймпад (`Ui/GameInput.cs`): левый стик/D-pad — движение и меню, A —
  подтверждение в меню и огонь, B — назад (в игре — пауза), View — карта. Клавиатура работает
  параллельно и в изометрии двигает по осям комнаты, как до геймпада.
- **Звук:** 19 процедурных эффектов (2–5 вариантов), живой электронный эмбиент, отдельные громкости эффектов/музыки.
  (Переработка звука под новые события — ещё впереди.)
- **Инструменты/тесты:** извлечение карт из ATR, сверка комнат со скриншотами, 83 xUnit-теста.

## 5. Как устроен кадр (важно при правках рендера)

Порядок в `GameApp.Run`:

1. `BeginDrawing`, очистка чёрным.
2. `SceneRenderer.RenderShadow(world, alpha)` — depth-карта света в FBO 2048 (переключает FBO и
   сбрасывает матрицы, поэтому вызывается до настройки letterbox).
3. `SceneRenderer.RenderGlow(world, config)` — только эмиттеры (силовые поля, «шапки» генераторов,
   снаряды, барьеры pod, глаза Shadow, маяк робота, кристалл прыгуна, частицы) в FBO 320x180, затем
   два separable-блюра. Тоже переключает FBO, поэтому тоже до letterbox.
4. Расчёт viewport/scissor: кадр 1280x720 вписывается в окно с полями 16:9.
5. 2D-ортопроекция `0..1280x720` (UI рисуется в этих координатах и масштабируется в viewport).
6. `Draw`: сцена, HUD, меню.

`SceneRenderer.Draw`:

1. `Rig.BeginView()` — кастомная ортопроекция 16:9 (`Raymath.MatrixOrtho` + `MatrixLookAt`).
   `Raylib.BeginMode3D` не используется: он берёт аспект из окна и искажал бы сцену.
2. `LightingShader.Begin()` → `DrawWorld(...)` — пол, закрытые зоны, столбики, объекты, танк, враги,
   Shadow (всё непрозрачное, освещается и отбрасывает тени).
3. Там же, ещё под шейдером: `DrawJumpers(...)` — прыгуны освещаются (грани кристалла), но с выключенной
   записью глубины, потому что они полупрозрачные.
4. `LightingShader.End()`.
5. Без света: снаряды обеих сторон, частицы (`ParticleFx.Draw`), название комнаты, pod-барьеры
   (аддитивные), силовые поля.
6. `Rig.EndView()`; `_glow.Composite()` — готовое свечение аддитивно поверх сцены (2D-проход в
   координатах 1280x720, поэтому строго после `EndView`).
7. 2D-подпись «?» для mystery.

`RenderShadow` рисует в карту глубины только «кастеров»: столбики, объекты, танк, врагов (прыгун —
силуэтом кристалла). Пол в карту не пишется, иначе он затенял бы сам себя. `RenderGlow` пишет в свой
FBO только эмиттеры (без теста глубины: сравнивать не с чем), блюр — 9-tap гаусс по горизонтали и вертикали.

Подводные камни, уже проверенные на практике:

- Перед `Rlgl.DisableDepthMask()` нужен `Rlgl.DrawRenderBatchActive()`. Иначе raylib сбрасывает
  накопленный батч уже без записи глубины, и полупрозрачное ложится поверх столбиков. Это же
  обязательно для прыгунов и частиц.
- Полупрозрачный объект **не должен писать глубину**, иначе он прорезает дыру в полу за собой. Прыгуны
  рисуются в освещённом проходе (нужен свет на гранях), но под `DisableDepthMask`; снаряды и частицы —
  в неосвещённом проходе.
- Тень-текстура привязывается через `Raylib.SetShaderValueTexture(...)`: raylib трактует id текстуры
  как юнит сэмплера. Ручная привязка к юниту 1 через `Rlgl` не сработала.
- `LightViewProjection = Matrix4x4.Multiply(Rlgl.GetMatrixProjection(), Rlgl.GetMatrixModelview())` —
  порядок аргументов именно такой (raylib хранит матрицы column-vector стилем).
- Танк, дрон, робот и прыгун рисуются через `Rlgl.PushMatrix/Translatef/Rotatef`. rlgl трансформирует
  вершины на CPU, поэтому `fragPos` в шейдере остаётся мировым. Если заменить на шейдерный model-матрикс,
  тени на модели поедут.
- `DrawCylinder`/`DrawCylinderEx` в raylib: у `DrawCylinder` `position` — **центр основания**, а не
  середина; у `DrawCylinderEx` задаются две точки и два радиуса (так строятся усечённые конусы и
  бипирамиды). На этом легко ошибиться при подгонке высот.
- MSAA 4x включён на окне; FBO тени и FBO свечения — без MSAA.
- Свечение (`GlowMap`) растеризуется в FBO 320x180 (1/4 кадра). Это отдельный проход без геометрии,
  поэтому сравнивать глубину не с чем: эмиттер за стеной всё равно светится. Для bloom это приемлемо,
  но не пытайтесь «починить» это тестом глубины в этом FBO — нужен depth-буфер основной сцены.
- `_glow.Composite()` вызывается только после `Rig.EndView()`: это 2D-квад в координатах 1280x720,
  в 3D-проекции он уедет. И только до HUD — интерфейс не должен светиться.

## 6. Что сделано в этой итерации (16.11.2026)

**Масштаб и свет**

- Введён `RoomMetrics`: один масштаб для всего, что стоит в комнате (1 единица = 1 клетка). Стена
  (силовое поле) = 0.5, столбик 0.9x0.5, pod-барьер = высота стены, танк 0.73, враги не выше 0.96,
  предметы до 0.96, Shadow 1.45.
- Стены и столбики уменьшены вдвое (1.0 → 0.5): при 1.0 панели в изометрии перекрывали танк и врагов.
- Свечение (`GlowMap`): эмиссия в FBO 1/4 кадра, два separable-блюра, аддитивная композиция.
- Тени: карта 1024 → 2048, PCF 3x3 → 5x5 с радиальными весами, меньший bias.

**Игрок**

- Танк переделан под читаемый силуэт; корпус опущен на половину высоты гусеницы (высота 0.73).
- Поворот стал правилом симуляции: `Heading`/`PrevHeading` + `UpdateHeading`; пока остаток больше
  `TurnToleranceDeg`, `MovePlayer` не двигает — «сначала разворот, потом движение». Тайминги:
  45° ≈ 4 тика (67 мс), 90° ≈ 5 (83 мс), 180° ≈ 7 (117 мс). Выстрел не ждёт доворота.
- Снаряд вылетает из дула (`GameConfig.MuzzleLength` = 0.74) и выглядит как пуля: цилиндр диаметром
  с дуло + конус на носу, на высоте ствола `RoomMetrics.BarrelY`.

**Снаряды и эффекты**

- `Rendering/ParticleFx.cs`: вспышка и искры у дула, дымный шлейф с огнём в хвосте (эмиссия по тикам,
  не по кадрам), взрыв со вспышкой, искрами и дымом. Дым — альфа, свет — аддитив, всё светится и в glow,
  на паузе замирает. Потолок 700 частиц.
- Снаряды врагов приведены к тому же масштабу: плазменный шарик 0.085 с ядром 0.045, свой след из
  угольков, вспышка у стрелка на каждый свежий болт.

**Плита в изометрии**

- `RoomFloor.Mask` строит доступную зону: BFS от клетки игрока по `Empty` + одно кольцо соседних
  `Thin`/`Thick`-клеток + клетки под всеми генераторами, чтобы посты стояли на плите и не висели.
  `RoomFloor.MergedBoundary` отдаёт осевые рёбра, склеенные в длинные сегменты (без посеточных швов на стенах).
- `RoomView.DrawPlateauFloor` рисует пол merged-runs по маске, сверху — тёмные металлические плиты (2×2, по 1×1 на неровных краях) с фаской и швами; `DrawPlateauSides` — стену на каждом ребре и
  угловой куб в каждой вершине. Боковины идут в **нелит-проходе** двумя плоскими тонами: южные грани
  (снизу-слева вверх-вправо на экране) — тёмным `CliffShade`, западные — базовым `CliffColor`; угловые кубы —
  базовым цветом, без тёмной накладки; под каждым генератором — колонна 1.02 × depth базового цвета, на ней
  стоит пост. На боковинах — тёмные вертикальные прожилки (`Veins`), детерминированы номером комнаты.
  Освещение и тени на них не считаются, поэтому нет затенённой возвратной грани и ложных «выемок». Chamber — толстый
  «+», коридор — форма прохода; снаружи обрыв.
- Плита включается при `Rig.IsometricBlend > 0.5`; верхний вид не меняется.

**Предметы**

- `SceneRenderer.DrawItem` и четыре модели: `KeyModel` (кольцо-головка, стержень, бородка), `KeyholeModel`
  (диск с чёрной скважиной), `PlusModel` (зелье) и `QuestionModel` (mystery). Все левитируют, высоты —
  `RoomMetrics.PropHover` / `KeyholeHover` / `StandingPropHover`.
- Ключ и скважина лежат плашмя в обеих проекциях; ключ вращается вокруг вертикали (30°/с), скважина
  неподвижна. Плюс и «?» в изометрии стоят вертикально и вращаются вокруг вертикальной оси, сверху лежат и
  не вращаются; наклон считается по `CameraRig.IsometricBlend`, поэтому переключение вида плавное.
- «?» дополнительно рисуется в glow-проходе; 2D-подпись «?» удалена за ненадобностью.

**Враги**

- Случайный окрас: `EnemyPalette` (магента, янтарный, голубой, багровый; Body/Light/Dark), без зелёного.
  Слот выбирает симуляция при появлении (`Enemy.ColorIndex`, `EnemyColorCount` = 4) — детерминированно.
- Spiral Drone по референсу: «тарелка» R 0.58 со шпильками и сужающаяся башня с тремя щелями; дрон
  смотрит на игрока, щели на ±0.35 рад совпадают с углами веера — болты летят из щелей.
- Robo-Droid упрощён: две гусеницы со светлой плитой, корпус, барабан-башня с тёмным пазом и бегущим
  красным маяком. Стреляет из башни на высоте паза; корпус плавно доворачивается по оси движения
  общим `EaseHeading`.
- Snap Jumper: прыжок стал настоящим телепортом (2 клетки раз в секунду, только в свободную клетку),
  эффект — кросс-фейд: призрак на старом месте гаснет, тело проявляется на новом. Облик — гранёный
  кристалл с вращающимся ядром и двумя осколками; в покое мерцает (0.35…1.0 непрозрачности).

**Инфраструктура**

- `assets/config.json` добавлен в `<Content>`: теперь попадает и в `bin`, и в `publish` (раньше в publish
  игра молча брала дефолты).
- Отладочные флаги `--fire` и `--shotframe N`; отладочные прогоны (`--shot`, `--fire`) больше не пишутся
  в таблицу рекордов.
- Убран неиспользуемый `AudioManager._frame`: сборка без предупреждений.
- Документация (DESIGN/TECHNICAL/README) обновлена по ходу работ.

**Ввод**

- `Ui/GameInput.cs`: клавиатура и первый доступный геймпад опрашиваются раз в кадр. Левый стик/D-pad —
  движение и навигация по меню, A — подтверждение/огонь, B — назад (в игре — пауза), View — карта.
  Клавиатура работает параллельно; горячее подключение пада поддерживается (поиск 0..3 каждый кадр).
- Края для меню считаются по предыдущему состоянию. Стик в меню срабатывает по ведущей оси с мёртвой
  зоной 0.6, чтобы диагональ не прокручивала список и не меняла значение в одном кадре.
- В изометрии экранным является только стик: `CameraRig.ScreenToRoom` пересчитывает его вектор в оси
  комнаты по текущей камере («вправо» — диагональ вниз по комнате, «вправо-вверх» — прямо по оси X).
  Клавиатура всегда двигает по осям комнаты (как до геймпада). Базис следует за анимацией камеры,
  поэтому при переключении вида удерживаемый стик плавно доворачивает танк.

## 7. Известные ограничения и подводные камни

- `assets/config.json` копируется в выходной каталог и в publish, но приоритет у исходного дерева:
  `GameApp.ConfigPath` ищет вверх каталог, где есть и `assets`, и `src`. Это и есть F5-сценарий; если
  правило поменять на простое `File.Exists`, игра начнёт брать копию из `bin` и правки перестанут
  подхватываться без пересборки.
- Прыжок Snap Jumper — это телепорт (раньше был быстрый рывок за 5 тиков). Кросс-фейд «здесь гаснет,
  там проявляется» требует именно телепорта. Если по геймплею окажется слишком жёстко — вернуть рывок
  можно в ветке `SnapJumper` в `UpdateEnemies`.
- Выстрел не ждёт доворота танка: пуля летит по `FaceX/FaceY`, поэтому в момент разворота уходит чуть
  в стороне от ствола. Так задумано; гейт по `Turning` в `Fire` — если понадобится.
- Силовые поля, pod-барьеры и название комнаты не освещаются (осознанно), у них своя эмиссия/аддитив,
  поэтому тени на них не падают.
- Шейдеру нужен OpenGL 3.3. Если он не собрался, `LightingShader.IsAvailable == false` и сцена
  рисуется без света (игра не падает). Свечение при этом продолжает работать: у `GlowMap` свой шейдер,
  и `Composite` проверяет только его валидность.
- Extent карты теней (`ShadowMap.HalfExtent = 27`) рассчитан на комнату 40x22. При смене размера
  комнаты/камеры править.
- `artifacts/` в `.gitignore`: ATR, PDF и скриншоты комнат на новой машине отсутствуют. Для сверки
  комнат их нужно принести отдельно.
- Локальная папка `ShamusRemake/` (publish-выход для запуска игры вручную) тоже в `.gitignore`.
- Рендер не покрыт тестами: проверяй через `--shot` (и `--view`, `--room`, `--settings`, `--zoom`/`--look`,
  `--fire`, `--shotframe`).
- Настройки и рекорды лежат в `%APPDATA%\Shamus3D\settings.json` и с репозиторием не переносятся.
- Геймпад не покрыт автотестами: проверять вручную. B на титульном экране ничего не делает (выйти из
  игры геймпадом нельзя), выход — клавиша Esc.
- CI (GitHub Actions) нет: сборка и тесты запускаются локально.
- Если правишь ассеты, помни: файлы копируются в выходной каталог при сборке.

## 9. Проверка перед коммитом

```bash
dotnet build Shamus.sln
dotnet test Shamus.sln --no-build
```

Ожидаемо: 0 ошибок, 0 предупреждений, 83/83 теста. Для визуальной проверки:

```bash
dotnet run --project src/Shamus.Game -- --maze c64 --room 3 --view iso --mute --shot shot.png
dotnet run --project src/Shamus.Game -- --settings --mute --shot settings.png
dotnet run --project src/Shamus.Game -- --winsize 1000x700 --room 3 --view iso --mute --shot bars.png
# эффекты: выстрел и попадание
dotnet run --project src/Shamus.Game -- --maze c64 --room 18 --view iso --mute --fire --zoom 6 --look 15,11 --shotframe 21 --shot boom.png
# враги в разных окрасах
dotnet run --project src/Shamus.Game -- --maze c64 --room 80 --view iso --mute --shotframe 8 --shot room80.png
```

Если в `settings.json` включён `Fullscreen`, `--shot` снимет полноэкранный кадр. Для оконных
скриншотов выключи fullscreen в SETTINGS/VIDEO или временно поправь `settings.json`.
